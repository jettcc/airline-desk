# M5：对话、Skills 与工具编排计划

状态：2026-09-20，首版已实现并进入逐项交付复核，实际覆盖见 [DELIVERY_AUDIT](../DELIVERY_AUDIT.md)。本文保留已确认设计与验收要求；当前实现、测试结果和未覆盖边界分别见 [DESIGN](../DESIGN.md)、[VALIDATION](../VALIDATION.md)，不以计划预期替代实际通过。

## 目标与范围

用户用中英文表达政策咨询、找票、改签、取消/退款等需求；助手能识别意图和缺失信息，选择工具并解释权威结果。不让用户理解内部模块或填写开发参数，不以模型回复作为办理成功证据。

支持跨轮补充、切换意图、明确目标、解释金额和失败恢复。公开咨询无需登录；私有任务先登录。超出 PDF 范围、事实不足或工具故障时如实说明，不靠模型常识补政策。

## 模块与技能组织

| 部分 | 职责 |
|---|---|
| ConversationService | 服务端保存对话/轮次、身份和依赖授权，消息幂等、顺序及上下文范围 |
| ModelAdapter | 单一可配置模型服务，结构化工具调用及用量/错误映射 |
| SkillRegistry | 版本化的说明、输入约束、允许工具和共享算法引用 |
| ToolGateway | 统一 schema、身份/对象权限、次数限制、错误及幂等键绑定 |
| ResponseComposer | 按受信事实/引用形成中文或英文解释和业务卡片 |

首版按 policy_consultation、booking_lookup、change_quote、cancel_refund、disruption_options、baggage_check、review_and_recovery 组织业务 skills。固定算法（时间窗口、费用、税费、额度、行李）复用 M2 函数及技能配套代码；底层加减不额外消耗一次模型调用。不得另写技能专用费率或许可判断。

Skill 包含适用范围、缺失事实、工具调用步骤、来源引用规则、允许状态及失败处理。所有 skills 属于项目审核内容，不从用户上传文档动态加载代码。注册表只启用声明兼容当前工具契约版本的技能。运行时不向模型暴露任意 shell、数据库、发布或维护工具。

## 典型流程与状态

轮次接收 → 验证身份/对话归属 → 识别意图及目标 → 必要时澄清/要求登录 → 查询政策或订单/候选 → 后端判断/报价 → 展示可确认结果 → 网页直接确认 M4 → 查询和解释最终状态。

对话输出分为已回答、待补充、需登录、待用户确认、政策不允许、需审核/已记录、已完成、暂未完成。具体资格与事实状态沿用 C06，不用对话的“完成”字段覆盖 Operation。

- 未知航司不默认，明确比较时分航司回答；当前选票作为已验证上下文，换票后重新计算。
- 多张可见票时先明确目标。用户说“我们都改”只能在已授权且明确选择的范围内推进。
- 合并一次询问当前真正缺少的关键字段；不反复索要后台已经有的数据，不要求用户填出票时间/原票价来覆盖数据库。
- 用户改变旅客、航段、日期或动作，通过受控对话/报价服务更新业务意图版本，使旧报价服务端失效并重新查/报价；不凭“还是刚才那个”猜报价。仅询问现有报价解释不变更方案。
- “直接帮我办”“确认”等聊天表达只引导到已明确的确认卡片，模型工具不能提交财务业务。
- 收到已提交操作的恢复请求，直接查已有记录，不重新报价后自动再办。

## 可调用工具与权限

模型可以调用 search_policy、get_booking、search_change_options、quote_operation、create_review_case、get_review_case、get_submission/get_operation；不能调用 confirm_quote、任意身份切换、审批、规则发布、样例重置或任意代码执行。

报价和审核保存属于可控的中间记录，不改变订单/资金。创建审核单需要当前明确办理意图及合法范围，工具用可信业务判断填来源/原因；重复调用绑定当前轮次/决定的稳定键。

ToolGateway 强制校验参数、对象权限和 schema；actor、session、规则映射、评估时刻及请求键由服务端注入。M2 的纯计算入口不直接开放给模型提交伪造价格生成正式报价。公开示例计算与正式订单报价分开标识。

## M1 适配与证据

保留现有 Python CLI/API，通过本地进程适配调用明确 release 的查询；首版每次受控启动查询进程，避免引入新的常驻检索服务。参数数组调用且 `shell=false`，执行路径固定，子进程环境不包含模型密钥；输入只含必要公共主题/航司/时间，限制长度、输出大小和执行时长。

应用先从 C04 获取匹配知识版本，将 epoch 毫秒转换为明确 UTC 的 ISO 输入，传 `--release`。检索失败不回退模型记忆中的政策。子进程开销在实施后测量，只有新证据表明需要优化才改为常驻适配；不重写第二套检索语义。

FOUND 只代表证据候选。已知主题用完整关联章节及核对事实/规则模板回答；不能因某段包含数字就推断适用。引用使用服务端验证的 source_id、版本、页码，经 M6 映射到允许的 PDF 快照，不能开放任意本地文件路径。

## 准确性和结果表达

政策条件、金额及操作状态由结构化事实和 M2/M4 结果渲染为主要内容；模型负责意图、槽位、选择有效引用、澄清以及对话衔接。对业务信息不直接展示未经核对的自由生成金额、许可或成功承诺。

来源 ID 必须属于本轮或报价固定版本的证据，金额卡和状态卡不能由模型直接构造。格式/引用检查只能验证结构与归属，不能证明任意自由文字语义正确；实施时对政策事实采用受控模板，并在真实模型验收中审阅完整回答。模型输出不符合契约时修复一次，仍失败则返回已验证的事实摘要/明确无法回答。

纯问候和一般非私有对话可直接回应；航空业务之外不假装有工具能力。未覆盖的航空问题明确说明，不能把“没有找到”变成政策允许或禁止。中英文切换只改变表达，不改变事实与计算。

## 顺序、身份变化与恢复

同一对话仅一个处理轮次；重复 message_key 相同内容恢复原轮次，异参拒绝。新的并发消息给出正在处理提示，不把乱序答案覆盖当前需求。不同用户/不同对话独立，服务有有界模型调用池和队列；超额明确稍后重试，不无限积压。

新轮次开始时先持久化处理中状态，M4 暂停该对话报价确认，避免新需求尚在识别时旧方案被提交。仅解释报价时，轮次结束可恢复仍有效原报价；改变意图则失效旧报价。失败/超限/重启将轮次结束或置中断，不留下永久忙状态。状态转换与确认共用数据库排序，执行模型期间不持有数据库锁。

游客登录按 C07 新建账户对话、只转移已标记公共答案/来源，不继承未核验私有意图。换号或授权撤销后，在下一次工具调用、组装上下文以及发出结果前重新校验；停用失效业务历史。长模型调用回来时已失效的输出丢弃，不能绑定到新用户。

首版只流式展示进度事件（理解、查资料、准备报价），不逐 token 展示尚未核验的业务结论。最终结构化回答通过校验后一次发布。断线重连按轮次/提交编号查证，进度结束不代表业务成功。

## 模型限制、费用与降级

固定最多 8 轮工具交互、一次结构修复、只读失败至多一次有界重试；中间记录写入重试必须复用原键。超限返回已知状态及必要下一步，不猜成功。技术调用超时为有限可配置值，在实施的模型合同测试中固定并记录；不改变票务政策/报价时间。

用户最新指定 Right Codes、GPT‑5.6 Sol 并提供限额 5 美元的 Key，配置和探测结果见 C09；当前用户域名的文本/工具往返已验证，模型流必须完整结束且参数校验通过后才可执行工具，目标模型响应字段不匹配时必须失败，不能静默降级。兼容性不因模型列表可见而成立。不实现多模型自动切换，以免改变行为和费用而未核实。缓存公共政策可按知识版本/语言复用，私有内容不跨身份缓存。

没有模型凭据时可以运行规则/工具/UI 模拟测试，页面明确模型未配置；不把脚本回复作为真实模型验收。模型不可用时仍可从业务查询入口恢复已提交结果，不能阻塞用户查证资金状态。

## 测试与交付

验证缺航司、多票澄清、部分字段补齐、改意图、提示注入、伪造身份/金额/版本、工具格式错误、跨语言一致、政策未知、工具超限、模型故障、网络断开、重复消息、换号/撤权后迟到输出。

工具调用测试验证实际调用及后台状态；真实模型通过 M8 的 A01–A10 并留下 trace 和语义审阅结果。固定模型 mock 只用于确定性故障测试，不计真实模型通过。
