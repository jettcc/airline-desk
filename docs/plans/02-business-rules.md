# M2：业务模型与规则计算计划

状态：2026-09-20，首版已实现并进入逐项交付复核，实际覆盖见 [DELIVERY_AUDIT](../DELIVERY_AUDIT.md)。本文保留已确认设计与验收要求；当前实现、测试结果和未覆盖边界分别见 [DESIGN](../DESIGN.md)、[VALIDATION](../VALIDATION.md)，不以计划预期替代实际通过。

历史实施约定：先完成全部模块计划与跨模块复核，再实施；该计划门槛已完成。模块编号不表示开发先后顺序。参见 [总计划](../PLAN.md)。

## 目标与用户预期

根据可信订单事实、用户选择、适用时间及经核对政策，回答能否办理、哪些部分需要补充或审核、应收/应退多少、资金去向及依据。相同输入与规则版本必须产生相同业务结果。

用户看到的结果必须区分政策允许、系统是否支持自动办理、信息是否齐全和实际操作是否完成。M2 给出计算与判断；M4 才签发报价和提交订单变化，M5/M6 解释并展示结果。

## 按依赖拆分内部模块

| 层 | 子模块 | 责任 |
|---|---|---|
| 基础 | Money、时间戳、稳定标识、版本与来源引用 | 约定格式、有效范围、精度、比较方式；不依赖模型或数据库 |
| 事实 | 客票、航段、价格、税费、附加服务、使用状态、航变及剩余权益的只读快照 | 校验结构、范围及一致性；不自行查询或修改数据库 |
| 规则 | 适用政策、资格、例外优先级、时间窗口、人工审核原因 | 匹配经核对规则；不通过检索排序决定金额 |
| 计算 | 改签、取消/退款、独立退税、行李、旅行额度 | 使用统一 Money 运算，按人/段/票输出分项 |
| 结果 | 可办理范围、缺失事实、金额与去向、理由和来源 | 提供稳定结果给 M4/M5/M6/M7；不宣称执行成功 |

M2 依赖事实接口而不依赖 M4 的数据库实现。M4 组装快照并调用 M2，因此提供订单事实不构成 M2 反向调用 M4 的循环依赖。公开政策问答可以不提供身份；涉及私有客票的快照必须先经过 M3/M4 权限控制。

## Skills 与计算核心的关系（已确认）

固定算法均可整理为可复用的 skills 及其配套代码，减少模型逐次推导和重复处理；复用计算核心，不额外维护一套 skill 专用公式。实际性能收益在实现后测量，不因封装成 skill 就预设已加速。

按业务任务组织面向对话的 skills，例如改签报价、取消与退款、航变选择、行李核对。Skill 描述何时使用、需要哪些事实、调用哪些工具、如何解释金额、何时补充信息或转审核；可以包含参考资料和调用共享代码的辅助脚本。底层算法可以作为这些 skills 共用的代码单元，不要求每次加减运算都增加一次模型工具往返。技能粒度、加载和工具适配见 [M5](05-dialog-skills.md)，业务工具通过 M4 调用本核心。

线上调用链：用户需求 → M5 对应 skill → M4 受控报价工具 → M2 资格与金额计算 → M4 保存可确认报价 → M5/M6 展示。提交时 M4 再使用同一个 M2 核心复核。

- 固定公式实现在可测试的共享业务函数中，skill 不复制第二套计算实现或独立费率表。
- Skill 可以引用公式帮助解释，但最终金额只来自受控工具；模型不自行执行任意生成脚本处理订单。
- 用户或模型只能选择动作和目标；价格、授权、已退款额、政策包和请求时刻由服务端取得。
- Skill 本身不赋予访问或写入权限，不能以技能已运行代替用户确认。
- Skill 的格式、加载、工具适配和版本兼容按 M5 计划实现；业务正确性不依赖模型是否正确遵循文字说明。

## Money 表示和运算（已确认）

采用 `google.type.Money` 的币种、整单位、小数单位结构语义。Google 定义 `units` 为 int64 整货币单位、`nanos` 为十亿分之一单位；本项目不因此引入 Google 云服务，也不预先决定使用 gRPC。已选 TypeScript，以 BigInt 实现精确运算；遵守结构语义，不引入 Google 云依赖。

例如 USD 123.45 的 JSON 表示：

```json
{"currencyCode":"USD","units":"123","nanos":450000000}
```

统一遵守以下运算契约，具体库随技术栈确定：

- 两部分均为整数，不使用二进制浮点数表示或计算小数金额；JSON 的 `units` 用十进制字符串，避免大整数在传输时失真。
- 统一 Money 运算提供加、减、比较、乘非负整数及取最大/最小；各业务规则不分别处理进位/借位。
- 内部统一换成 BigInt 整数纳单位：`units × 1_000_000_000 + nanos`，精确运算后还原为规范 Money。中间量不用 int64 直接相乘，以免溢出；使用 TypeScript/JavaScript 原生 BigInt。
- 输入必须满足 nanos 范围及与 units 的符号一致性；输出规范化并校验 int64 范围。拒绝非法结构，不让超范围、异号或截断悄悄通过。
- 本项目仅支持 USD 收退；币种不一致不能相加，不自动换汇。保留 currencyCode 为未来扩展边界。
- Money 类型与通用运算保留最多 9 位小数的表达能力，不在通用类型中一律截断到分。本期票价/税费等业务输入及最终可结算金额采用 0.01 USD 精度，即这些结算相关值的 nanos 必须是 10,000,000 的整数倍。当前政策公式为加减、取正数及整数倍，无需猜测分摊/税率或舍入方式。需要结算但超过分精度的来源报数据问题；未来出现更高精度的业务中间量或比例分摊时，先确定舍入发生的边界与规则，再启用相应业务路径。
- 已支付票价、税款、退款/收费行金额使用非负值，另记方向；金额差允许负数。现金流、本人旅行额度和不可退价值分别表达，不能仅用负金额暗示所有业务含义。
- 数据库按 C02 保存币种、规范整单位文本和整数 nanos，与 Money 精确、无损往返并验证范围；不得用浮点列或 SQL 浮点聚合。

Money 是金额表示规范；正确的进位、借位、精度控制、范围校验和业务抵扣规则仍由本项目运算层负责。

## 时间戳与时区

用户已确定使用时间戳。采用 UTC Unix 毫秒整数，字段明确标记单位（例如 `received_at_ms`）；接口编码及有效日期范围以 C03 为准，不混用秒和毫秒，不接受缺少时区的墙上时间作为绝对时刻。

- 原始出票、当前/原始起飞、航变通知、完整请求接收、报价过期、操作提交、额度签发/到期分别保存，不能互相代用。
- M2 显式接收评估时间，不读取客户端时钟或自行取当前时间；M4 从服务端时钟取得并保留请求接收时间，测试可注入固定时刻。
- 同一绝对时刻用不同 UTC offset 表达，转换后必须得到同一业务结果。时间戳不包含旅客或机场时区，展示和自然语言日期解析另用明确的时区信息。
- “明天早上”等由 M5/M6 结合用户明确的日期语义和时区解析；无法确定时追问。M2 接收已明确的候选时间，不能猜用户时区。
- 当前三份政策统一按 UTC 判断：24 小时、30 天、365 天按实际经过时长；航变替代航班的前后 7 个日历日按 UTC 日期比较，不能误写为相差不超过 168 小时。
- 完整有效请求到达服务端的时间决定窗口；排队和落库时间另记。资料缺失、未授权或未接受具体报价的早期请求不能保留资格。M4 将首次完整有效接收时刻绑定不可变 Submission，最终同库复核；报价有效期已确认 5 分钟，等于到期时刻即失效。
- UI 可展示明确标注时区的当地时间；切换显示时区不能改变资格、费用或有效期。

## 事实输入与结果输出

以下是已与依赖模块对齐的语义契约；共同类型遵循 CONTRACTS，实际工具 schema 在实施时据此细化并验证。

输入包括动作、选定客票/航段、候选新行程、经权限裁剪的事实快照、评估时刻和经启用的规则组合。

快照包含：所属航司/渠道、原始出票时间、现有及候选票价类型、原始/当前航班时间、路线端点及国内国际属性、使用/误机状态、逐项票价/政府税费/附加服务、已处理与剩余权益、支付渠道引用、航变事实、各记录版本。具体操作只要求与该判断相关的必要事实。

输出至少包含：

- 动作与精确目标范围、每张票/每个权益部分的判断。动作资格与票价/税费分项是否可退分开；Basic 票价不可退不等于完全未用票不能取消或退未用税。
- 允许、政策不允许、缺事实、需审核、未覆盖或数据冲突；系统不支持某条自动路径须单独说明，不能冒充政策禁止。
- 缺少哪些事实、稳定原因标识、是否具备生成完整报价的条件。
- 每行金额的种类、方向、币种、旅客/客票/航段或权益标识、原支付渠道引用/额度归属、计算输入和公式标识。
- 应收、现金应退、额度发放、不可退部分分别汇总。经济净变化只是解释项，不能作为跨渠道合并执行的指令。
- 源文档/版本/章节/页码、规则包、知识快照、事实版本和评估时刻。不含模型隐藏推理。

`允许` 只表示给定事实下符合规则。M2 不锁座、不写订单、不签发可执行报价、不证明授权持续有效，也不返回“扣款/退款已完成”。

## 核心规则和计算

先校验适用范围与事实一致性，再识别合格航变保护；航变保护优先于普通自愿及误机价值损失。非保护路径再判断使用状态、误机、时间窗口、票价和路线。对不能自动核定的部分保留已知权利并标明审核范围。

| 请求 | 计算与边界 |
|---|---|
| 自愿改签 | 按每位旅客每个改动航段累计改签费；正差价为各段 `max(新票价−旧票价, 0)` 的和。每段负差价不退、不发额度、不抵扣他段或手续费。费用表已含该手续费相关税，不重复加税 |
| 升档 | 政策允许且新旧价格、税费、整票票价类型一致性明确时纳入；本次按现有票价类型收费，后续请求按替换类型；原出票时间保持不变。降档禁止，混合票价或不明确的已用部分分配转审核 |
| 税费调整 | 政府税费逐项增收或原路退回，与票价分开；缺少实际税额不能按零。未定义的跨项/跨渠道净额结算不自动执行 |
| 普通整票取消 | 每位选中旅客的完全未使用客票，按整票规则计算 `max(合格票价−取消费, 0)`，根据政策发现金退款或本人旅行额度。取消费超过票价不追加收费；部分航段/已使用部分不得猜比例 |
| 附加服务 | 自愿取消已购行李/座位不退；合格日期/时间改签的未使用服务在同人同路线下按可用性转移，不可提供转审核，不能默默丢弃或承诺现金退款 |
| 独立退税 | 仅核定明确未使用、尚未退还的政府税费权益，不隐含取消；有效乘机权益与退税冲突未解决时转审核 |
| 合格航变退款 | 完全未用的受影响行程退全票价、未用政府税及未用附加项，原路退、取消费零；部分使用时保留未用受影响部分退款权，金额/分配交审核 |
| 合格航变改签 | 满足同航司、目的地、票价类型、前后 7 个 UTC 日历日及可用座位等条件的一次免费替代出行；已退款的同一权益不能再改签 |
| 行李 | 按人按段判断免费额度、每件尺寸重量及文档明确加购费用；超限、更多额外行李转审核，不以付费替代接受条件 |
| 旅行额度 | 归属具名本人、同航司、不可提现或转让；M4 实际签发时确定开始时刻，精确 365 天到期，兑换及新旅行开始须严格早于到期；M2 预览不能冒充已经签发 |

三家费率和边界不在此复制维护，使用 [POLICY_GUIDE](../knowledge/POLICY_GUIDE.md) 对照原文形成经审核的规则包和独立测试期望。历次改签费用是否追溯退款、换票后未定义的价值分配、真实银行到账等不擅自补规则。

数字验收锚点：

- NSA Standard 一人改两段、提前 30h，新旧差分别 +30/−40 USD，手续费 2×25，税额分别 +8/−5：应收 88、原路退税 5，现金经济净支出 83；没有 −40 抵扣。
- NSA Standard 提前整票取消，票价 100、未使用税 20、座位 10：本人额度 60、现金退税 20、座位不退。
- NSA Standard 提前取消，票价 20、税 10：额度 0、退税 10，不追加收取不足抵扣的取消费。
- BHA Basic 合格航变，整票未用，票价 200、税 30、未用行李 40、未用座位 10：符合其他条件时原路退 280，不套用普通 Basic 限制。

## 新版本发布与历史结果

每个可执行业务版本是不可变的兼容组合：知识快照、源 PDF 指纹、规则包及输入输出契约版本。M1 原有 `CURRENT` 仅为证据查询指针，不能让业务运行独立读取一个新知识版本和一个旧规则版本。

已确定更新流程（C04）：导入暂存 → 原文/表格/例外差异核对 → 更新规则及独立测试期望 → 规则/回归/引用校验 → 明确生效区间 → 原子启用整个兼容组合。任一步失败不发布不完整组合。

- 每次查询或计算固定一个组合，不跨版本拼接来源、费率和公式。M5 解释具体报价时引用该报价的版本。
- 选择政策版本依据适用请求时间和各版本生效区间；规则内部的原出票日期条件另行判断。不能用“最新导入”代替“当时适用”。
- 历史版本及历史报价/操作保留，不因更新重写过去已完成结果。新规则不自动重新扣款或退款。
- 旧报价在提交时校验适用组合和当前事实；规则/政策更新导致组合不兼容则要求新报价与重新确认。知识索引重建若希望复用旧规则，必须有明确兼容记录，默认不静默复用。
- 新规则启用与旧报价提交的并发切换由 M4 保证一致；不能先校验旧组合，再未经保护地按已失效组合提交。不可变文件先验证并加载，适用区间映射在业务数据库切换，最终提交同库读取，详见 C04 和 M4。未来生效发布不影响旧组合在其有效区间服务。
- 更新失败后，旧组合只能服务其仍适用的范围；已知旧政策失效且缺少新可执行规则时，暂停受影响自动报价/办理，说明资料或规则尚未就绪，不能以回滚名义套用过期政策。
- Skill 中若包含业务解释，应标明来源或动态引用同一组合；主要版本约束由服务端检查，不能只要求模型记住版本号。

## 与 M4 的原子性合同

用户已明确要求同 M4 协调。以下业务条件已由 M4 的单库短事务、版本与唯一约束、Submission/Operation 恢复方案承接，运行正确性仍待测试：

- 一次确认绑定一个精确的目标集合与报价；集合内所有客票变化、库存变更、模拟收费/退款/额度、权益消费及报价消费须一起提交或全部不变。
- M4 在一致的最新事实下调用 M3 复核当前身份与授权，再调用同一 M2 规则核心复核业务时间、价格、政策组合及可处理权益；并发变动时冲突或重报价，不能覆盖他人结果。授权/会话失效与提交的先后约束见 [M3 计划](03-identity-sessions.md)。
- 幂等键相同请求恢复原结果；同报价换键不能再次执行；不同报价也不能重复消费同一可退权益。M2 接收到已退款事实不等于可以独立防住并发退款，最终由 M4 状态约束保证。
- 任一选中旅客的请求动作需审核、被拒绝、缺事实或无库存时，不默默办理其他旅客；某项票价退款为零不单独构成动作被拒绝。可以显示逐人原因并请用户明确选择新的子集，再生成新报价。
- 提交后响应丢失按操作记录查询，显示未核实或恢复既有结果，不能凭超时推断失败并重做。
- 本期原子性范围是本地模拟业务及账本，没有真实外部支付参与。以后接外部支付须另设计支付结果、补偿与对账，不能沿用单库事务作全局成功保证。
- 模型调用、检索和等待用户不进入持有业务写锁的事务；M2 的纯计算应可在必要的短事务内复核。

## 验收设计

以下列出验收要求；当前逐项证据见 [交付复核](../DELIVERY_AUDIT.md)，计划检查本身不构成实现通过。

| 组 | 必须验证 |
|---|---|
| 精确金额 | 小数进位/借位、零与负差额、符号规范、int64 边界与超范围、超过 JS 安全整数的无损往返、币种不一致；通用 Money 支持纳单位的精确往返，USD 业务结算拒绝无舍入规则的超分精度；0.10+0.20 精确为 0.30 |
| 费率覆盖 | 三航司全部票价×相关国内/国际×时间窗口；BHA 原出票分界前/等于/后，重签不重置 |
| 资格优先级 | 普通禁止与航变保护、误机与退税、部分使用保护、升档/降档/混合票价、渠道路由及资料未覆盖 |
| 时间与跨时区 | 起飞前 24h 的前/等于/后 1ms、恰好起飞；同一时刻不同 offset 结果一致；秒毫秒误用拒绝；30 天、365 天与 UTC 7 日历日边界、跨月跨年 |
| 资金分项 | 逐人逐段正差价，负差价不抵扣；取消费封底零；税费/额度/附加服务分开；未知税额不作零；已处理权益不重复列为可退 |
| 输入与输出 | 同输入同版本重复和并发调用结果一致；不存在用户状态串用；缺失/矛盾事实不能形成完整报价；每个关键结论和金额可追到来源 |
| 版本更新 | 新旧生效区间、原出票条件独立、新资料旧规则不匹配阻断、失败发布、旧结果可复查、旧报价兼容性失效、已知旧政策失效时停止错误回退 |
| Skill/工具一致性 | 调用入口与提交复核使用同一核心；伪造金额/版本/身份不被采纳；切换语言或绕过 skill 文案不能改变工具层业务结果 |
| M4 联合验收 | 两旅客操作中途失败全回滚、同票竞争、末座竞争、重复确认/不同键/不同报价的权益防重、权限撤销、规则发布与提交竞态、响应丢失恢复 |

测试期望从原文和人工核对的算例独立建立，不能直接调用被测公式生成期望。政策权利、计算准确、授权状态、持久化原子性和用户提示分别核对。M2 单元通过不替代 M4 联合或真实模型网页验收。
