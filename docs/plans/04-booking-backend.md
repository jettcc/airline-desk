# M4：有状态预订后端计划

状态：2026-09-20，首版已实现并进入逐项交付复核，实际覆盖见 [DELIVERY_AUDIT](../DELIVERY_AUDIT.md)。本文保留已确认设计与验收要求；当前实现、测试结果和未覆盖边界分别见 [DESIGN](../DESIGN.md)、[VALIDATION](../VALIDATION.md)，不以计划预期替代实际通过。

## 目标与完成定义

把合法且被明确确认的报价变成持久化模拟业务：改签后航班真实改变，取消后票不能再次使用，同一权益不能重复退；刷新、重启和响应丢失后可以查证结果。多人一次操作全成或全不变。

范围涵盖本人/代理访问、候选航班、报价、确认、改签、整票取消、合格航变选择、独立退税、模拟收费/退款/额度、审核单存储及操作查询。真实支付、外部航司、多实例、行李购买、新票购买和人工审批不在范围内。

## 技术与模块

采用 TypeScript / Node.js 24 LTS + Fastify，better-sqlite3 管理本地业务 SQLite；React 网页由同源服务提供。使用单实例模块化单体，共享业务数据库，使会话/授权变更、政策映射与业务提交可排序。不在模型等待期间持有写事务。

M1 Python 独立保留；M5 的本地适配调用检索。M4 只使用已经加载并核对的 M2 规则包、版本引用，不在交易内启动 Python 或解析 PDF。

| 子模块 | 职责 |
|---|---|
| Repository | 数据迁移、约束、一致快照及短事务 |
| OfferService | 从模拟目录返回航班/票价/税费/服务可用性，不锁座 |
| QuoteService | 组装事实、调用 M2、保存不可变报价 |
| SubmissionService | 确认准入、幂等收据、提交及结果恢复 |
| Settlement | 模拟资金行和权益余额，原路去向/本人额度 |
| PolicyRegistry | 经过核对的来源与规则组合生效映射 |

## 数据模型与范围

| 实体 | 内容与不变量 |
|---|---|
| Booking | 同一航司/渠道下客票集合；集合访问不赋予全体客票权限 |
| Ticket | 旅客、统一票价类型、原出票时间、当前版本/使用状态；同行各有独立版本 |
| Segment / Coupon | 路线端点、原始/当前时刻、航班及是否使用/误机/暂停；已用部分不被改签覆盖 |
| Offer / Inventory / Reservation | 新航班及价格版本、政府税分项、服务能力、座位数量和每票持有关系；座位不能为负或重复释放 |
| PriceComponent / PaymentRef | 每票/段明确票价、政府税、附加服务，实际支付来源；没有原价分配信息则不猜 |
| Entitlement / Consumption | 未用、已用、已处理的明确权益及剩余值；按政策和状态决定可处理范围 |
| Quote | 身份/会话/对话/范围、候选方案、分项金额、依据、目标版本、价格版本、创建/到期时间和不可变摘要 |
| Submission | 操作者与幂等键、内容摘要、首次完整有效接收时刻、运行代次和状态 |
| Operation / Ledger / Refund / Credit | 成功操作及目标版本变化、分项资金/权益消费；一笔成功操作可关联多行原路退款与额度 |
| Session / Authorization | M3 定义的会话/授权有效性及版本，置于同业务库以便提交复核 |
| PolicyBundle / Assignment | C04 中的不可变组合及按请求时间适用的映射 |
| ReviewCase / Trace | M7 定义的审核记录和独立诊断轨迹；不替代成功 Operation |

Money 保存币种、规范 units 文本和 nanos 整数，M2 用 BigInt 精确运算；不在 SQLite 用浮点聚合。时间为经过范围校验的 Unix 毫秒整数。所有外部 ID 为不含秘密的不透明标识，仍必须鉴权。

持久化只存一份当前客票真相及不可变操作/分项变更记录，不引入完整事件溯源平台。已成功记录不覆盖修改，维护重置只作用于专用演示数据库。

## 逻辑服务接口

| 服务 | 输入与输出 |
|---|---|
| get_booking / list_accessible_tickets | 从会话取身份，按权限返回可见票及小计；不存在/无权统一受限 |
| search_change_options | 已授权目标与明确日期/时间偏好，返回有版本的模拟候选及报价所需税/服务数据 |
| quote_operation | 动作与选定候选/客票，返回完整报价或缺事实/不允许/审核等逐项结果；不信任模型输入金额 |
| confirm_quote | 仅可信网页入口：报价、确认凭据、幂等键；返回已提交、明确拒绝或可查询收据 |
| get_submission / get_operation | 当前身份下按原键/编号恢复事实，未找到不自动判未执行 |
| create_review_case / get_review_case | 遵循 M7 独立审核行为及 M3 最小访问范围 |
| activate_policy_bundle | 本地维护操作，非模型工具；先完整校验再切换生效映射 |

业务 schema 不允许 actor_id、规则版本、价格或已确认标记由模型任意覆盖。查询、报价、确认、重试与记录读取均执行对象级校验。

## 查询和报价

读取订单与财务时固定一致快照；按作用范围校验身份和授权，再调用纯 M2。保存报价前重新核对读取版本；若已变化则刷新计算。报价包括完整应收、原路应退、额度、不可退及服务转移信息，缺任何影响总额/资格的事实不能生成可确认报价。

报价按 C03 保留 5 分钟，不预扣座位。库存数量变化只要仍足够且价格/时刻/条件未变，可以通过最终可用性检查；价格、目标票状态、条件或适用规则变化要求新报价，不能自动接受更高金额，即使某项恰好更便宜也需新确认。

每个对话的当前报价引用及业务意图版本持久化。生成新报价或确认改变业务范围时，旧报价在服务端置 SUPERSEDED；最终提交检验当前引用和版本。页面禁用旧按钮不能代替此校验。

新对话轮次与确认通过同库状态排序：模型理解新需求期间暂停当前对话确认，提交事务检查该状态；先完成的确认可被后来的轮次读到。轮次结束后依实际意图恢复或替换原报价，按 C07 处理，不能在模型尚未识别目标变化时执行旧方案。

保留/升档候选由模拟目录明确给出全票一致性和各受影响段金额；M2 校验旧票类型决定本次费用、原出票时间不变。多段部分升级导致混合票价、不明历史换票价值等不能自动补算。

## 确认与原子提交

阶段 A：完整请求到达时捕获服务端时间。校验输入和当前访问权限后先查 `(actor_id, idempotency_key)`：相同内容恢复原收据，不同内容拒绝，不能因原报价现在过期而否认已经成功。新请求再校验会话、对话/报价绑定、TTL、轮次状态和明确确认，保存不可变 Submission。收据不锁座、不产生票款变化；重新登录优先用受权限控制的结果查询入口恢复旧业务。

阶段 B：在 `BEGIN IMMEDIATE` 短写事务中完成：

1. 检查服务运行代次及收据状态；成功即返回既有结果，已拒绝/中断不再次运行。
2. 从同库复核当前会话、逐票授权、有效期、对话轮次/当前报价及目标票版本，记录决定时刻；撤权/退出、新轮次与此通过同库事务排序。
3. 按收据的有效接收时间选择 C04 适用规则组合，比较报价；复核航班/报价事实和当前权益。
4. 调用同一 M2 核心，比较精确范围、条件、金额和去向。差异则拒绝旧确认，要求新报价。
5. 分组计算目标库存变化，按 reservation 释放原座位并占用新座位；同航班替换按净变化校验，不能双占/双释放。任意目标无位则全部失败。
6. 更新所有目标票/航段版本、服务转移关系、权益余额；保存账本/退款/额度、Operation 及确认依据；消费报价并把收据标成功。
7. 一起提交，随后按权限返回权威回执。任何业务写入/必要凭证失败显式回滚，不在事务内捕获错误后继续提交。

事务内全部同步，不执行网络、模型、知识检索或等待用户。数据库忙只作有界重试；超过限制保持准确的未完成/待核实状态，不绕过校验。busy/IO 错误发生在 COMMIT 周边时重新查询权威记录，不能无条件认定失败。

## 权益、状态与逆向流程

- 自愿取消只处理选中旅客整张未使用票。票状态与相应现金/额度/退税一起提交；部分目标需审核时不自动办理其余人。票价退款为零不等于取消动作被禁止，M2 的动作资格与分项权益分别使用，保留未用退税。
- 税费独立申请只消费明确未用未退权益，不隐含整票取消；有效乘机权益冲突未解决则审核。取消已退过的税不得再次退。
- 航变保护先由 M2 判断，免费改签和退款对同一保护权益互斥；一笔完成后另一旧报价失效。新合格异常使用独立事件/选择权益，不能误用前次免费资格。
- 票面额、实付资金、已消费权益和未退价值分别记录；不能把历次手续费算进本次可退票价。原文未定义的历史价值分配交审核，不靠账本余额创造权利。
- 自愿改签产生的新行程事实、补价、税费和服务转移一起保存。低价变化不发隐藏额度，不将差额用于以后自动返还。
- 改签只改未用且符合政策的航段；未飞事实和误机需以模拟使用事件/事实为依据，不把网页时区或用户自称作为乘机记录。
- 误机后剩余段暂停，不自动恢复；已完成或已用部分不能因新的请求回退。模拟航变、登机/误机事件由受限样例/维护入口提供，不由聊天修改。
- 代理渠道退款转本地审核/路由记录，不声称航司系统已直接退至银行卡；直接渠道产生模拟原路退款记录。
- 额度签发使用当前事务决定的签发时间及具名旅客/航司归属，发放与客票取消同事务；不实现额度兑换购买新票。

## 幂等、崩溃恢复和查询

强约束包括 Submission 的操作者/键唯一、成功 Operation 的 quote_id 唯一、资金行与消费关系唯一、余额和版本检查。相同操作不同键不能复办同报价；不同报价也不能重复消费同一权益。

服务启动按 C05 更新运行代次并恢复旧 RECEIVED：有成功 Operation 就返回原结果；无成功记录则置 INTERRUPTED，阻断旧处理器后续执行，要求新报价。没有未经确认的后台自动补办。测试必须证明 COMMIT 前崩溃全回滚、COMMIT 后崩溃可恢复一次成功。

查询不到、网络不可用、日志缺失分别标明；只有明确终态才说未执行。相同键重试的返回仍经过 M3 当前权限，用户退出再登录不会导致新增操作。

混合多人操作的查询按当前有权票输出分项和可见小计，不返回原全单人数/总额；不可安全分离的详情整体受限，完整原始记录仍留存本地受限审计。

## 数据生命周期和初始化

迁移采用版本表和事务；样例初始化可重复，默认拒绝覆盖已有业务数据。显式 reset 仅用于指定的演示/测试数据库，不能通过模型调用，不接触政策原文件。

业务库启用外键、WAL 和正常持久化配置；禁止 dirty read。知识快照与业务库分开，联合启用通过 C04 映射实现。运行单实例，所有会话/授权/发布维护写入遵守同一事务入口。

## 验收重点

完整覆盖 C02–C07 和 M8 的 A02–A10。特别检查：同票竞争、不同票可分别成功、多人第二张失败全回滚、末座不超卖、升档一致性、税费去重、规则发布竞态、撤权竞态、已取消票重放、同键异参、换键同报价、不同报价同权益、数据库忙/磁盘错误、两侧崩溃与响应丢失恢复。

数字预期由政策核对与独立样例给出。检查票、库存、操作、收据、账本、权益余额的持久化数量与内容；HTTP 成功码或聊天宣称不是验收证据。

## 取舍与依据

SQLite 适合本期单实例短事务；不宣称生产吞吐或多机能力。库存与财务都为本地模拟，未来真实支付需要重新设计外部结果、补偿和对账。

依据：[SQLite 事务](https://www.sqlite.org/lang_transaction.html)、[隔离](https://www.sqlite.org/isolation.html)、[better-sqlite3 API](https://github.com/WiseLibs/better-sqlite3/blob/master/docs/api.md)、[Node 发布周期](https://nodejs.org/en/about/previous-releases)。这些支持事务/运行时选择，不能代替本项目权限、幂等和业务测试。
