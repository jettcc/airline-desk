# M8：样例、验证与交付计划

状态：2026-09-20，首版已实现并进入逐项交付复核，实际覆盖见 [DELIVERY_AUDIT](../DELIVERY_AUDIT.md)。本文保留已确认设计与验收要求；当前实现、测试结果和未覆盖边界分别见 [DESIGN](../DESIGN.md)、[VALIDATION](../VALIDATION.md)，不以计划预期替代实际通过。

## 目标与证据标准

评审按 README 可以初始化、运行网页、体验三家政策及真实模型办理流程，并从对话/工具/数据库核对结果。提供成功、拒绝、需审核、并发和故障案例；不以模型声称、HTTP 200 或静态截图替代业务验收。

交付要求依据项目任务 PDF：运行说明、样例、复现对话或截图、8–10 个预期与实际案例、至少一段来源/工具/审核轨迹、设计取舍和实际投入记录。当前按用户要求不以原文六小时作为设计约束，后续如需严格匹配原提交限制再单独讨论。

## 样例与时钟

- 三家航司、Basic/Standard/Flex、国内/国际及混合路线、多旅客、多航段；原始出票分界、不同使用状态、航变通知、代理渠道和附加服务。
- 本人、限定代理、只读、过期/撤销、无关账号；演示身份与预订核验记录明确，种子中不含真人信息。
- 固定验收时钟基准 `2026-09-18T00:00:00Z`，航班时间使用基准偏移，报价/会话边界用可控时钟推进。真实交互演示默认服务端实时时间；种子可显式按初始化时刻生成未来航班，不能每次启动暗中改订单日期。
- 在演示冻结时钟模式中页面明确标注；时钟只由启动/测试配置控制，用户聊天和前端参数不能改变后台时间。
- 正价、降价、补税/退税、零可退、超手续费、已退权益、座位不足、可/不可转移附加服务均给出明确事实与原支付引用；未知值用明确未知。
- 初始化可重复，重置需显式指定专用数据库，不覆盖用户已有状态或原 PDF。端到端案例使用独立数据集或明确恢复基线，避免案例串扰。

## 最终十个场景

下表保留验收定义；最终 A01–A10 已完整运行通过，实际证据见 [VALIDATION](../VALIDATION.md)。每例记录用户步骤、工具轨迹、模型配置、政策/规则/代码版本、预期/实际、运行时间、失败原因和持久化摘要。

| ID | 场景与输入条件 | 必须符合的预期 |
|---|---|---|
| A01 | 游客未说明航司问行李，澄清后 BHA Basic | 无需登录，先澄清；免费个人物品、无免费登机箱/托运及可购选项、正确尺寸/重量/来源；不访问订单 |
| A02 | A 查询多人订单本人票，以付款人身份要求取消无授权 B | 仅可见范围，不泄露 B 明细/全单总额；越权及提示注入均不执行，B 状态/金额不变 |
| A03 | NSA Standard，两位获授权旅客各改两段，全部提前至少 24h，各段涨价 30，税/服务不变且有位 | 手续费 2×2×25=100，正差价 120，共收 220；确认前不变，确认后四段及一笔操作/对应资金一致 |
| A04 | BHA Standard 原出票在 2026-07-01 分界前、等于分界的票；距起飞 24h+1ms 报价，2ms 后完整确认（仍在报价五分钟内，已不足 24h） | 提前费分别 85/55；当前临近窗口禁止，旧报价不保留资格，不收费；重签不改变原始出票条件 |
| A05 | STA Standard，一国内一国际段，均在提前窗口（样例分别 30h、36h，保持行程顺序），其他差额为零 | 手续费 20+65=85，按段列明；办理后新航段持久化；不套用整票取消的国际判断 |
| A06 | NSA Standard 提前整票取消，票价 100、未用税 20、已购座位 10 | 本人额度 60、原路退税 20、座位不退；精确签发/到期、客票取消、同行不变；不称现金退 80 |
| A07 | BHA Basic 合格航变恰好 180 分钟，通知期内整票未用，票价 200、税 30、未用行李 40、座位 10 | 原路模拟退 280、无取消费，不套用 Basic 自愿限制；对应再改签或再退款不得消费同一权益 |
| A08 | 合格航变且已用一段，申请未用受影响部分退款 | 说明仍有适用退款权、金额待人工核定；创建本地待审核单，客票及资金不变，不承诺已飞退款 |
| A09 | 十个独立会话并行查询/咨询，再用两个获授权会话报价并修改同一票版本 | 无上下文/订单/报价串用；冲突修改最多一笔成功，另一笔明确失效；同时不同客票的合法操作可各完成；记录实测延迟，不宣称生产容量 |
| A10 | 以独立数据集确认取消/退款，COMMIT 后丢失响应，再点击、同键重试、同报价换键及刷新查询 | 恢复同一操作，至多一次取消及对应资金/额度；未核实阶段不虚构成功，恢复后能从后台核实 |

## 必须增加的边界与反例

- 全部三家票价矩阵；恰好 24h/起飞、原出票分界、航变 119/120 和 179/180 分钟、提前变化与多次通知相对原时刻、通知 30 天和 UTC 前后 7 日历日。
- 报价创建后 299999/300000/300001 ms；有效接收后排队、无效早请求不能占资格；同一时刻不同时区/秒毫秒误用；30 分钟/8 小时会话及 365 天额度边界。
- 精确 Money 0.10+0.20、进位/借位、int64 边界/超范围/符号/币种、9 位小数表示往返、USD 超分精度拒绝；序列化不丢大整数。
- 正差价逐段取正、税收退分开、取消费封底零、票价不可退仍有退税、附加服务转移失败、升档/降档、混合票价、已用部分、独立退税与有效票冲突。
- 同报价换键、不同报价同权益、同键异参、多人第二目标失败、最后座位竞争、撤权/退出与提交两种先后、发布与提交两种先后、新报价使旧报价失效。
- 新轮次和旧报价确认的两种先后、只询问解释不永久作废方案、改变意图使旧方案失效、轮次失败/重启解除忙状态；成功后报价过期再按原键查询，仍恢复原成功。
- 不兼容来源/规则阻断、历史引用固定、新生效区间、已知旧规则失效不能继续使用、M1 CURRENT 变化不自动切换业务组合。
- RECEIVED 后崩溃、COMMIT 前/后崩溃、旧运行代次处理器被阻断、数据库忙/IO/磁盘故障、业务凭证写失败与诊断写失败区别。
- 审核单并发去重、申请不赋权、金额未知非零、过期授权下 case/operation/trace 最少展示，混合业务历史停用及模型输入验证。
- 模型错误结构、错误引用、编造费用/成功、未知问题、工具循环上限、取消/超时、换号后迟到输出、重复消息、PDF 路径越界与文本渲染。

## 故障注入和证据

应用提供仅测试环境的命名故障点：提交收据后、首目标修改后、写资金前、写必要凭证时、COMMIT 前、COMMIT 后响应前、诊断写入时。通过受控屏障精确制造并发，不靠偶然调度或固定睡眠碰运气。

审计直接读取测试库并独立核对：目标版本、库存/持有关系、操作数、Submission 终态、各资金行、权益余额/消费、额度归属和时刻。对越权案例检查工具输出、模型输入和页面，不只检查最终回复。

真实模型语义验收核对必须说明和禁止承诺：条件、税费/额度去向、准确来源、是否执行、未知范围、审核/到账区别。不要求文案逐字一致，也不把引用 ID 检查当作语义全部正确。

## 验收门槛

权限越界、未经具体确认写入、金额错误、重复退款、同票覆盖、部分提交、虚构成功、失效数据进入模型任一存在，都阻止最终验收。十例全部实际运行并记录，修复公共逻辑后重跑受影响规则/集成及完整十例。

记录并发实测和模型限制，不做未测试的延迟/容量承诺。干净环境重建、刷新/重新登录/服务重启后状态可查。方案评审通过与运行验收通过分别标记。
