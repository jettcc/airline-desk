# M7：人工审核与执行记录计划

状态：2026-09-20，首版已实现并进入逐项交付复核，实际覆盖见 [DELIVERY_AUDIT](../DELIVERY_AUDIT.md)。本文保留已确认设计与验收要求；当前实现、测试结果和未覆盖边界分别见 [DESIGN](../DESIGN.md)、[VALIDATION](../VALIDATION.md)，不以计划预期替代实际通过。

## 目标与范围

用户能区分办理成功、申请已记录、确定未执行和结果待核实；评审能从政策依据追到实际订单及资金结果。首版创建、去重、查询本地模拟审核单并导出脱敏轨迹；不做审批后台、真实客服接入、外部联系、证件上传或银行到账承诺。

## 模块划分与来源

| 部分 | 职责 |
|---|---|
| ReviewCase | 记录明确办理请求的人工核定原因、已知权利、未知信息和申请归属 |
| OperationView | 读取 M4 已提交事实并按 M3 权限展示；不建立第二套业务成功状态 |
| Trace | 关联检索、规则/工具请求与脱敏结果、版本及相关操作/审核编号 |
| Export | 本地导出虚构验收案例的 JSON/Markdown 轨迹，保留完整性状态 |

政策要求来自 [核对资料](../knowledge/POLICY_GUIDE.md) 中的部分使用退款、医疗、授权/监护、服务不可用及未知范围；执行记录交付来自任务书。所有隐藏推理、密钥、完整证件/卡号和会话原始凭据均不记录。

## 审核创建与数据

- 已登录用户明确要求办理，可信业务结果为需审核时，说明原因并创建本地单；普通咨询仅解释政策/审核路径，不自动建单。
- 业务审核由 M4/M2 的已核验结果提供原因和来源，不能信任模型编造的“已符合退款条件”。一般授权核验申请可保存申请人主动提供的最少说明，但不查询未获授权目标的私有事实。
- 字段包括 case_id、申请人、请求幂等标识、类型、经允许的目标范围/用户声明引用、事实及规则版本、已知权利、待核定项、待补信息、来源、创建时间戳、关联会话/轮次。
- 金额未知用显式未知，不用 0；“有权申请未用部分退款”和“金额尚未核定”可同时存在。
- 本期唯一处理状态为 RECORDED_AWAITING_REVIEW（已记录，待人工接入）。所需材料只列说明，不假装存在上传通道，也不提示向虚构邮箱发送真实证件。
- 不创建虚假的 APPROVED、REFUND_PAID 或正在人工处理状态；已有权限也不因工单创建而扩大。
- 原办理的客票/资金保持不变。单的创建成功与业务操作成功独立，页面明确说明。

## 幂等、并发与失败

同一 `(applicant_id, request_key)` 对应唯一审核请求；参数摘要不同则拒绝复用。由稳定轮次/业务决策引用绑定 request_key，模型不能每次重试生成新身份或替换范围。并发重复请求由数据库唯一约束保证同一编号。

事实变化后的新申请产生新编号并关联旧单，不按模糊文本自动合并不同诉求。保存失败不返回虚构编号；响应丢失按同一请求键恢复。只创建审核单的事务不修改订单或财务。

## 必要业务凭证与诊断日志

M4 在业务事务中保存 Operation、目标/版本变化、确认依据、政策组合、金额和权益消费关联。必要凭证失败，业务事务回滚。M7 的 OperationView 只读取这些权威记录。

诊断轨迹包含 trace_id、会话/轮次、工具调用标识、来源片段/规则标识、已脱敏输入输出、错误类别、耗时及操作/审核关联。工具参数只留白名单字段；不保存任意完整请求头/原始模型输入输出。

诊断写入失败不能回滚或重做已提交业务。最终业务回执与 trace 完整性分开；导出检查必需事件，缺失时标记 INCOMPLETE，不填造日志。数据库不可用时页面显示暂未核实，不能把“未查到”直接解释为未执行。

## 访问与保留

查询审核单、操作、轨迹均复核当前身份和对象权限。申请人可看自己的授权核验申请最小状态，不因此获得目标旅客数据；撤权后遵守 M3/C07 的历史停用和记录裁剪规则。网页不提供任意 trace_id 跨用户检索。

本地交付导出仅针对显式指定的虚构案例，提供不含秘密的审计视图；不把调试导出工具暴露给对话模型。模拟记录持久保留至维护者显式重置测试数据，不设置自动清理导致幂等历史失效。重置只影响独立演示数据库，不改原 PDF/知识快照。

## 输入输出与模块依赖

输入为当前申请/访问上下文、明确请求、可信业务决策和来源；输出为审核编号与准确状态、当前有权查看的业务回执或轨迹完整性结果。内部诊断不改变 M2 的资格判断和 M4 的提交结果。

- M3：对象授权、申请人最小状态和撤权后的数据范围。
- M4：审核存储复用业务数据库；业务凭证同事务，确认恢复以 Submission/Operation 为准。
- M5：绑定当前轮次，解释待核定原因，重复调用稳定复用 request_key。
- M6：显示模拟性质、已知权利、未知金额、待人工接入及查询入口。
- M8：从完整执行路径导出可重现轨迹，并验证无隐藏推理或秘密字段。

## 验收

1. 部分使用航变退款：保留权利、金额未知、生成单，订单和资金不变。
2. 纯咨询不建单；游客私有审核需登录；授权核验申请不泄露目标是否存在。
3. 同请求重复和并发创建只有一个单，参数不同不能复用键，新事实新单可追溯。
4. 审核记录失败不声称创建成功；响应丢失可按原键恢复。
5. 必要业务凭证失败导致 M4 全回滚；诊断轨迹失败不改变已成功业务。
6. 无权限/撤权后的 case、operation、trace 查询无泄漏，混合目标安全裁剪。
7. 真实模型演示轨迹串起证据、工具、报价、确认和结果；缺事件如实标不完整。

以上为计划，不预填通过。
