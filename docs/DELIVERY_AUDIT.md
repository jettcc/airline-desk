## 本次发现并处理的缺口

1. 普通政策问答原先主要显示可展开的英文原文，缺少约定的用户说明。新增绑定已核对知识 release 的双语摘要，费率从适用规则表取得；未知主题不生成答案，新 release 不自动套旧摘要。
2. 多人后端原子办理已有，但网页候选流程只覆盖单票。新增同一预订全部明确目标的组合候选卡，每人至少明确一个变更段再统一报价。补充真实 U01 首次还发现历史目录过大触发 CONTEXT_LIMIT，已压缩模型历史并加 M04 回归；未提高上限掩盖问题。
3. 行李组合按用户列举顺序分配免费/额外额度，可能把可接受组合判超限。改为合理分配，增加调换顺序与尺寸/件数边界，未改动 PDF 金额。
4. 不同航司分别绑定不同证据 release 时，原过滤条件可能带入其他航司的旧证据。改成精确“航司→release”归属；新增规则全表、必需来源声明和发布失败验证。
5. 医疗/监护/权属可查询政策，但缺少完整本地申请入口。补齐未核验申请、未知金额和最小权限；不新增审批、免手续费或退款承诺。
6. 审核缺少明确的会话/轮次/事实版本和新事实关联。已补齐。诊断仅检查起止事件可能漏报中段丢失，现按连续序列及工具成对事件判断，并导出关联业务结果。
7. 流内额度错误可能被当成普通断流重试；已区分，额度错误不自动重试。政策缺档不再阻断 bootstrap 和历史操作恢复。
8. 旧总计划与模块计划混有“尚未实施/全部 NOT_RUN”文字，已校正，计划预期与当前运行证据分开。
9. 真实回归发现模型有时用通用政策检索回答行李问题，原通用模板没有完整额度。补齐从同一规则核心产生的全票价中英文行李表；A01 按实际额度/费用/出处验收两条合法路径，而非锁定某个工具名称。
10. 撤销后立即恢复授权可能复用旧报价，已通过失败用例复现。数据库自动递增授权修订号，会话绑定该版本；权限改变即使后来恢复，也要新开会话、重新报价。补充 I04/I05 覆盖无中间读取和模型等待期间失权。
11. 原浏览器丢响应测试在服务器提交前就断言操作数，新增页面变化暴露测试竞态；改为等待实际提交屏障，保留失败日志。补充真实场景并行启动曾使用相同毫秒目录，现增加唯一后缀；原始 U01 失败、U02 通过及目录碰撞说明均保留，未将失败覆写为通过。

## 尚未覆盖和明确边界

- 本次是本机单实例、SQLite、本地模拟身份/支付/库存；真实实名、银行到账、真实航司/GDS、真正客服审批、多实例/生产容量不在已确认范围。
- 已做真实进程强杀、真实 SQLite 忙等待、SQLite 页限制产生的 SQLITE_FULL，以及命名提交故障；没有做真实硬盘拔除、主机断电或文件系统损坏实验。不能声称验证了所有硬件 I/O 故障。
- 分航司多 release 的适配用受控查询替身核对归属；当前三份真实 PDF 共用一个已审核 release。未来新 PDF 的语义正确性必须人工复核，不能拿这次通过替代。
- 支持当前计算代码下的规则/生效映射更新及历史引用；**旧计算执行器自动迁移仍未实现**。改动计算代码会阻止旧包被悄悄重解释。当前使用独立新演示库，旧库保留；不是无损线上升级承诺。
- 部分已用退款、选段取消、混合票价、未知历史分摊和无法转移服务进入审核，金额为未知；审核记录不等于有人处理或已批准。严重医疗事件也不保证例外。
- 额度可发放/归属/到期核对，不兑换购买新票；行李可核对，不销售；没有外部实时航班事件流。误机/使用/航变来自模拟事实，不能判断真实登机行为。
- 新增限定/失效授权样例通过测试夹具构造，不额外把所有测试身份塞进普通登录菜单；普通演示保留旅客、同行和代理三种入口。
- 有限测试不能穷尽模型表达。真实模型可能超时或断流，次数和缺失用量如实记录；没有供应商持续可用或固定延迟承诺。5 美元为用户提供的 Key 限额，无法由 token 数证明实际美元余额。

这些限制不会阻断当前作业功能交付，但应在答辩/提交说明中保留，尤其是原题六小时限制与当前授权范围的差异。
