# 跨模块共同契约

版本：v1，2026-09-20 交付复核补充。本契约已用于首版实现；实际验证见 [VALIDATION](VALIDATION.md)。本轮依用户授权敲定常规方案；金额与政策时间沿用已确认 M2，登录时限沿用 M3，报价有效期 5 分钟由用户单独确认。各模块不得自行复制后修改此处语义；变更同步更新相关计划和验收。

## C01：事实与责任

| 事实 | 唯一责任方 | 消费方与限制 |
|---|---|---|
| 原文、指纹、知识快照 | M1 | M2/M5 用明确版本；搜索命中不代表资格 |
| 规则包、资格、金额计算 | M2 | M4 以可信快照调用；skill/页面不另算一套 |
| 当前操作者、会话、本人/代理授权 | M3 | M4/M5/M6/M7 每次访问验证，不能从模型参数取身份 |
| 订单、库存、报价、权益、业务提交结果 | M4 | 只通过受控应用服务操作；界面/对话不自行推定成功 |
| 消息、需求及工具编排 | M5 | 需求不覆盖后台事实；登录/撤权后重新检查上下文 |
| 页面选择及确认事件 | M6 | 服务器验证归属，按钮不是权限证明 |
| 审核单、诊断轨迹及交付导出 | M7 | 必要业务凭证仍由 M4 原子保存，审核记录不授予权限 |
| 独立样例、预期、实际验收证据 | M8 | 预期不能由被测公式生成；NOT_RUN 不计通过 |

实现采用模块化单体：TypeScript / Node.js 24 LTS、Fastify、SQLite（better-sqlite3），网页 React + Vite；M1 保留 Python 工具，通过受控本地进程适配查询。库的精确版本及锁文件在实施环境检查时固定。选单体是为了让授权、报价、库存和模拟财务共享短事务；不引入分布式锁、消息队列或向量服务。

## C02：金额和权益

- 接口 Money：`currencyCode`、十进制字符串 `units`、整数 `nanos`；通用运算使用 BigInt 纳单位，遵守 Google Money 符号和范围。本期 USD 业务输入/结算精确到分，超精度不静默舍入。
- 存储为币种、规范十进制整单位文本及整数纳单位；运算在 M2 BigInt 核心完成，不使用 SQL 浮点或 JS Number 计算钱。往返范围/规范校验及金额对账属于必测项目。
- 每行金额有旅客/客票/航段或权益标识、资金种类、收/退/额度方向和原支付渠道引用。金额行非负；比较差额可负。现金、旅行额度、不可退价值分开。
- `Entitlement` 表达明确的票价/政府税/附加服务权益、使用状态、剩余额度及来源分配。不是“付款总额减已退总额”即可证明可退；需匹配 M2 政策及真实模拟事实。
- 并发消费同一权益由 M4 同一事务校验余额及版本；取消后新报价也不能重复退税。不得用剩余余额大于零推断政策允许退款。
- 负票价差不产生现金/额度或手续费抵扣。前次改签费用追溯退款、未定义的换票价值分配、部分使用分摊缺规则时转审核；不新增金额口径。
- 原路退税和本人额度归属不随代理人变化。不实现跨支付渠道轧差、外汇或真实支付。

## C03：时间和报价

- 统一绝对时刻为 UTC Unix 毫秒整数，字段后缀 `_at_ms`，拒绝非整数、越范围及秒/毫秒混用。接口日期范围限定 2000-01-01 至 2100-01-01 之前，覆盖演示与测试；这只是本期数据范围，不扩写政策有效期。
- 展示附明确时区；本期默认 UTC。用户明确当地日期/时区时先解析，含糊的“明天”结合当前显示时区明确说明，不能猜机场时区。可提供同一时刻的不同时区显示，不改变规则结果。
- 政策的 24 小时/30 天/365 天按经过时长，前后 7 日历日按 UTC 日期。原出票、当前航班时间、通知时间、请求接收和提交时间分开。
- 报价 TTL 已确认 5 分钟：`expires_at_ms = created_at_ms + 300000`，完整有效确认请求必须在 `received_at_ms < expires_at_ms` 时到达；等于已失效。无锁座、无无条件锁价保证。
- `received_at_ms` 在完整请求体到达服务端时捕获；只有身份/确认/范围齐全且报价匹配的请求才可作为完整请求。聊天、缺字段请求、旧会话和伪造确认不能占用早时间。
- 报价 TTL 与政策窗口按该有效接收时刻判断，正常内部排队不改写时间。接收时仍有效不代表最终一定执行：提交前还要检查当前权限、订单/航班事实、库存、规则兼容性与金额。
- 同一有效提交的幂等重试使用已保存的首次有效接收时间和内容；请求被拒绝/中断后新报价使用新的接收时间，不能通过新请求重用旧资格。
- 登录默认空闲 30 分钟、最长 8 小时，沿用已确认 M3。主动用户交互可更新有效活动时间；后台轮询/心跳不延长空闲寿命。提交中授权与会话有效性的线性化点为最终写事务内的最后资格检查时刻，事务内无外部等待；撤权/退出与提交由同库写事务排序。
- 额度在模拟签发事务内分配 `issued_at_ms`，按此计算精确到期；最终响应取实际签发记录，预览只说明有效期规则。

## C04：发布与版本

`PolicyBundle` 为不可变的知识快照 ID、源指纹、规则包版本/校验值、输出契约版本组合。`PolicyAssignment` 按航司和请求时间区间映射到已核对组合。

新快照和规则先写完整不可变文件、校验、加载，再在业务数据库短事务内更新对应生效区间映射。M4 提交也在该库写事务内选择映射，因此更新与提交有确定先后。文件发布失败不更新映射；数据库更新失败只留下未启用文件，不产生半套业务版本。

应用模式下，公开政策查询和办理都先解析业务映射，再传明确 `release_id` 给 M1；独立 M1 CLI 的 `CURRENT` 仍只表示证据版本，不直接控制业务生效。具体报价解释使用报价自己的组合；历史记录保留原引用。

确认时按有效请求时间选适用组合并比对报价。组合不兼容则重报价/重新确认；新增未来生效政策不自动使其生效日前仍适用的旧报价失效。没有匹配政策、旧政策已知失效但新规则未就绪时停止受影响自动报价；不能任意回退。

一个请求固定版本，不边算边跟随指针。所有启用文件启动时验证并预载，事务内不读 PDF/启动进程；文件缺失/校验失败拒绝使用。应用提供维护命令启用组合，禁止模型/网页改发布映射。

## C05：查询、报价、确认、恢复

1. M3 确定操作者和访问范围，M4 取得一致快照；候选价格/税/服务由模拟目录给出，模型不能填最终价格。
2. M2 计算，M4 保存不可变报价及目标、金额、事实版本、来源组合、会话/对话绑定；报价不修改票或库存。同一对话保存新报价或确认改变业务目标时，事务更新 `active_quote_id`/业务意图版本，将旧报价置 SUPERSEDED；提交校验该版本，不能仅在页面禁用旧卡。
3. 网页确认入口提交 `quote_id`、确认凭据和幂等键。已绑定目标/金额只从服务端报价取，不从请求重复提交的数据取。先校验当前访问权限并查原键/内容：已有提交走恢复，不因现在报价过期而把过去的成功改成失败；仅新提交检查完整确认和报价有效期。
4. 服务端记录提交凭证 `Submission`，再进行最终短事务：复核身份/授权/时间/规则/状态/价格/库存/权益，调用同一 M2 核心；不一致则拒绝或要求新报价。
5. 更新所有目标票、库存、账本/退款/额度、权益余额、报价消费、`Operation` 及 Submission 成功状态，同一事务提交。任一失败全部业务变化回滚。
6. 同一 `(actor_id, idempotency_key)` 相同内容返回原提交；不同内容拒绝。每份报价最多一笔成功 Operation；换键或换报价也受权益余额/消费约束。
7. 响应丢失先按提交/操作编号查询。查不到或数据库不可用仅说明尚未核实，不能据此新建另一笔操作。

`Submission` 是请求收据，不是成功凭证，可以先于业务事务保存。它只有 RECEIVED、SUCCEEDED、REJECTED、INTERRUPTED 等可核实状态；SUCCEEDED 必须在业务事务里关联 Operation。执行过程不暴露“已经成功”的推测状态。

服务启动后通过运行代次隔离旧处理器；所有提交检查当前代次。对前一代遗留 RECEIVED，在同库事务中检查 Operation：有则恢复成功，无则标 INTERRUPTED 并禁止再执行该收据。不自动在重启后补办旧请求；新的办理需要新报价。旧处理器/重试不能越过终态。运行代次用于单实例崩溃恢复，不是多实例部署承诺。

## C06：状态不得混用

| 维度 | 状态语义 |
|---|---|
| 证据 | 找到、缺范围、未覆盖/不足、不可用；FOUND 不等于可以办理 |
| 规则结果 | 允许、政策不允许、缺事实、需审核、数据冲突；逐权益判断 |
| 报价 | 可确认、被新方案替代 SUPERSEDED、已过期/失效、已消费；当前事实仍需复核 |
| 提交/操作 | 收到请求、明确拒绝/中断、已提交；由持久化事实决定 |
| 用户对结果的认知 | 等待结果、暂未核实；不是对已提交记录的覆盖 |
| 审核 | 已记录，待人工接入；首版无批准/处理中/到账承诺 |
| 诊断轨迹 | 完整、不完整、不可用；不改变业务提交事实 |

一次请求可以票价不可退但税费可退。M2 分开返回请求动作的可执行性与每个财务部分的权益：例如完全未用 Basic 的自愿取消不能因票价现金退款为零就一概拒绝取消/退未用税。整个交易是否执行取决于全部选定目标的动作条件和完整报价，不要求每个财务部分都有正退款，也不静默部分提交。

## C07：访问、会话、上下文与展示

- 随机会话标识由 HttpOnly Cookie 携带，服务端存状态；同源部署，写入口验证来源/防跨站请求，生产传输配置不在本轮上线范围。登录、退出、撤权状态在业务库中与提交共用排序。
- 公开咨询不读取订单；私有工具始终按当前身份裁剪。未知对象与无权对象统一受限响应。逐对象权限不能仅依赖难猜 ID。
- 对话和轮次绑定身份/会话代次，换号清除旧选择/待确认卡，拒绝迟到结果。一个对话同一时刻最多处理一个模型轮次；重复消息幂等返回，新的并发消息提示等待/重试，不静默覆盖。
- 接收新轮次时在同库记录处理中状态；轮次结束前暂停该对话的报价确认，由 M4 提交事务复核。确认先提交则新轮次读取已更新事实；轮次先接收则旧确认等待澄清结束。只是询问报价解释时可恢复仍有效的原报价；改变目标时按 C05 失效旧报价。异常/重启使轮次明确结束或中断，不能永久占用。
- 游客登录时创建新的账户对话，只复制经标记的公共政策消息/来源，不转移用户自填订单号等自由文本或待操作意图；用户在登录后重新选择业务目标。旧游客对话不成为他人的账户历史。
- 失效代办授权关联的业务会话整体停用业务历史回放/模型上下文；新开对话继续允许业务，不做自然语言逐句脱敏猜测。
- 混合多人 Operation 只输出当前获授权票对应的分项及其小计，不暴露原全单总额/人数/失权目标。若无法安全分离则不给详情，不重写原始审计记录。
- 申请人能看自己的授权核验申请最小状态，但不能据此读目标订单。对已失权的其他业务审核单也仅保留申请编号及一般状态，不返回目标私有事实。
- 所有已完成记录仍以当前权限读取；退出不删除业务记录。完整记录导出只用于本地交付工具及虚构样例，网页无跨用户管理入口。

## C08：审计与事实输出

M4 的必要凭证和订单同事务；M7 的检索/工具诊断可以独立失败，但需报告轨迹不完整。创建审核单亦先持久化再返回成功编号。模型不可直接输出成功卡、审核编号或资金变动卡。

业务卡片、政策条件和金额由已核对事实/M2/M4 的结构化结果渲染；模型选择意图、工具、事实引用和追问。服务端验证引用归属及结构，引用存在不等于自由文案语义正确；不把未经验证的自由文案当业务事实，仍做真实模型语义验收。

公共解释用已核对规则/事实模板和来源组合，支持未绑定订单的咨询或示例，标明条件。纯问候可直接回应；未知业务问题明确未覆盖。不以固定十个问答脚本替代模型理解与工具流程。

## C09：实施前外部配置

模型通过单一可配置 `ModelAdapter` 接入，要求结构化工具调用能力。用户最新指定 Right Codes / GPT‑5.6 Sol 并授权使用其限额 5 美元的 Key；目标接口 ID 已改为 `gpt-5.6-sol`。用户调整渠道后，`https://www.right.codes/codex/v1` 的文本、模型字段、结构化只读工具调用和结果续答已完整复测通过；此前出现过一次工具流缺终态，不能据此承诺稳定性。M5 应验证完整终态再执行工具，不自动换模型。应用实现阶段该旧域名出现 TLS 重置，已按同供应商官方文档配置 `https://www.rightapi.ai/codex/v1` 并通过真实业务单例；完整状态详见 [接入记录](MODEL_CONNECTION.md)。适配器必须检查响应模型，异常明确失败；接入探测不替代真实业务验收。

模型费用不是票务金额，不使用旅客报价资金支付模型调用。精确依赖版本、模型调用超时/轮数等运行保护在实现中有界设置并记录，不改变已确认政策窗口、报价 TTL 或登录期限。


## 交付复核补充（不改变金额或时间口径）

- 公开政策摘要只能使用已核对模板和同一适用规则包中的数值；新知识 release 没有核对模板时只显示证据，不复用旧摘要。跨航司比较按各航司实际绑定的 release 分组，不能混入该航司旧 release。
- 多人选航班以同一预订内全部明确选择对象生成一个候选卡，所有人至少明确一个变更段后统一报价，不悄悄缩减旅客集合。
- 医疗、监护和权属争议可以记录未核验的本地审核申请；医疗目标需已有读取权限，监护/权属申请不查询他人客票。申请不批准例外、免手续费或退款，不收集证件/病历。
- 审核记录保存会话/轮次、客票事实版本及规则组合；业务新事实申请关联上一单。诊断使用逐轮连续事件编号，缺少中间事件也标 INCOMPLETE；导出将报价、提交收据和成功操作相联，仍不输出确认凭据或隐藏推理。
- 游客登录只复制经服务端工具核验的公开政策/行李卡，原始用户文本、订单自述和待办理意图不复制。
- 代理授权的对象、动作、有效期或撤销状态变化时，数据库自动递增授权修订号；业务对话绑定所用修订号。撤权后再恢复不能复活旧对话或报价，必须新开对话、重新报价；模型等待期间失权也不得发布旧私有结果。

## 本地账号补充契约（2026-09-20）

支持本地账号注册/密码登录，保存于现有SQLite文件；新账号不得按昵称/用户名自动关联样票。认证请求不经模型；账号创建、身份切换与会话轮换同事务，哈希等待后再次复核旧会话。演示身份独立入口，游客私有按钮禁用。详见[本地账号](LOCAL_ACCOUNTS.md)。
