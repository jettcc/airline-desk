# 实现设计与边界

本版目标是可核对的本地航空客服作业：三份给定政策、自然语言网页入口、当前授权事实、精确报价、用户明确确认、原子提交和可恢复结果。沿用全部模块计划；本文件说明实际实现，而非计划评审结论。

## 模块对应

| 模块 | 实现 | 关键边界 |
|---|---|---|
| M1 资料 | `src/airline_kb`、`src/assistant/knowledge.ts` | 不可变 PDF/FTS5；只按固定 release 启动受控 Python 查询，参数数组，无 shell，无模型 Key |
| M2 规则 | `src/domain/{money,time,rules,types}.ts`、`data/rules/policy-v1.json` | 资格/金额/时间确定性计算；复用同一算法，不让模型自行计算 |
| M3 身份 | `src/server/{identity,accounts}.ts` | 本地注册/登录与独立演示身份；逐票逐动作授权、会话时限、撤权后业务历史停用 |
| M4 办理 | `src/server/{db,booking,policies,seed}.ts` | SQLite 单实例、报价/收据/事务/资金/库存/权益/版本共同处理 |
| M5 对话 | `src/assistant/{model,skills,tools,conversation}.ts`、`skills/*` | Responses 完整终态后才执行工具；七个版本化 Skills；8 次工具循环上限 |
| M6 页面 | `web/`、`src/server/app.ts` | 同源 React 页面；可信业务卡、明确确认、原请求恢复、中英文/时区 |
| M7 记录 | BookingService 审核与操作视图、`traces`、`scripts/export_trace.ts` | 审核只是本地待处理记录；诊断与业务凭证分离 |
| M8 验证 | `tests/`、`tests-ts/`、`tests-browser/`、`scripts/acceptance.ts` | 单元、接口、并发屏障、进程崩溃、浏览器和真实模型分层证据 |

## 请求与资金路径

```mermaid
flowchart LR
  U[网页自然语言] --> C[会话归属与顺序]
  C --> M[Right Codes GPT-5.6 Sol]
  M --> T[严格参数工具网关]
  T --> K[固定版本本地政策]
  T --> R[授权事实与确定性规则]
  R --> Q[五分钟报价]
  Q --> UI[费用明细与具体确认按钮]
  UI --> A[完整请求收据]
  A --> TX[复核并原子提交]
  TX --> O[操作 客票 库存 资金 权益]
  O --> V[当前权限下查询与恢复]
```

模型没有确认、身份切换、重置、任意 SQL、文件、网络或发布工具。工具参数不能注入 actor、时间、原票价或金额。公开业务回答使用审核原文和受控卡片；未经核验的模型自由文字、费用或“成功”不会展示。通用政策咨询提供与知识 release 绑定的中英文核对摘要，费率表引用适用规则数据；同时保留英文原文与 PDF。新 release 尚未审核摘要时仅展示原文，不把旧模板套到新政策。

同一对话仅一个进行中的轮次；数据库登记忙状态后释放锁，再等待模型。新轮次处理期间不能确认旧报价。仅解释报价保留方案；其他工具保守地让旧方案失效。不同对话共享有界模型池，最多 3 个模型请求并行、12 个等待项、排队最多 45 秒。单次请求最多 45 秒，整轮最多 150 秒；传输/残缺流最多重试一次，参数最多修复一次，额度错误不自动重试。未完成流不执行其中的半截工具调用。

## Money、时间与政策

Money 使用 USD、字符串 int64 `units`、整数 `nanos`，BigInt 运算最多九位小数。具体业务结算必须到分；拒绝超分输入。页面按字符串格式化，不用浮点重新汇总。

每个航段分别取正票价差；降价不能冲手续费。政府税补收与原路退还分开，旅行额度与现金分开；取消扣费最低封零。未知历史分摊、部分使用退款或服务无法转移时进入审核，不猜金额。审核金额显式为 UNKNOWN/null。

业务时间只取服务器 epoch 毫秒，来源政策按 UTC；金额和时间边界遵循 PDF。5 分钟报价不保留更早的政策资格。完整、合法、获授权的确认请求先存 RECEIVED，再以该收据时间评估政策；队列等待不改变该时间，但提交时仍核对最新权限、版本和库存。首次不完整请求不能占住窗口。

未使用的前序航段已到起飞时间时，规则会按误机优先阻止后续自愿改签；显式 NO_SHOW/SUSPENDED 样例演示剩余权益暂停。首版没有外部航司运行事件流，也没有假装自动识别真实登机情况；USED、误机和航变事实来自模拟后台。航变保护先于自愿票价限制，部分已用退款只确认适用未用部分的权利，不退款已飞部分。

规则包包含证据 release、来源指纹、规则 JSON 指纹和计算代码指纹；每航司生效区间绑定联合包。旧报价固定原包，确认时重新选择当前适用包，不一致拒绝。维护工具信任经人工审核的本地规则文件；结构/指纹校验不是法律语义审核。仅支持本次已知版本的兼容升级：退改算法保留为字节指纹锁定的 `rules-v1.ts`，新版仅扩展托运行李尺寸输入；启动时原子更新适用关系并保留旧包/历史结果，旧报价重新获取。未知代码版本仍拒绝启动，不提供通用历史执行器迁移。

## 原子性、防重与恢复

一张报价可含同一预订的多位获授权旅客。确认事务写入：Operation、客票版本、座位持有、各资金行、税费/附加服务/航变权益消费、旅行额度、报价消费和 Submission 成功状态。任一失败全部回滚。

`(actor, idempotency_key)` 唯一并绑定内容摘要；同键同内容恢复旧结果，同键异参拒绝。Operation 的 quote_id 唯一；同报价换键也不重复。客票版本与权益消费唯一约束阻止另一报价重复退税/航变退款。库存先算旧座释放与新座占用的净变化，再同事务检查和更新；最后一个座位只能被一笔操作取得。

SQLite 使用 WAL、FULL synchronous、外键、约束、IMMEDIATE 事务和有限忙等待；只承诺单服务实例、本地磁盘。操作过程中不持有数据库锁等待模型。重启切换运行代次，旧 RECEIVED 按 Operation 查证为已完成或中断；旧处理器不得继续提交。提交后响应丢失时，原请求查询恢复同一 Operation，不以异常推断没执行。

必要业务凭证写失败会回滚；脱敏诊断失败不会回滚已完成业务。诊断记录连续编号、工具开始/结果/错误；导出检查起止与中间缺口，缺失标 INCOMPLETE。导出还关联同一会话的报价、Submission、Operation 和审核单，不补写成功。

## 权限与页面

演示账户不等于生产认证。本人由已建立的旅客关系授权；代理由含动作与时限的 grant 授权。付款人声明、名字、票号不授予权限。不可访问和不存在返回同类错误。后台再次检查当前权限，剪裁操作明细，不泄露整个预订的其他旅客。

多人候选以组合卡统一选择和报价。登录后只复制经核验的公开政策/行李卡，不复制游客自由文本。历史上下文绑定所用授权及其修订号；授权变更自动递增修订号，撤销后整段相关业务对话停用，即使恢复权限也不能复用旧报价。注销或失权后的迟到模型回复丢弃。浏览器共享 HttpOnly/SameSite cookie，写请求校验同源和 CSRF，窗口重新聚焦/周期检查会话变化。文本用 React 转义，不渲染模型 HTML。原 PDF 路径由允许列表映射，不能读取任意文件。

网页先显示查证进度，最终业务卡一次发布。原请求幂等键在本机按演示身份保存，断网/刷新可恢复；不存模型 Key。当前时间可切换 UTC、上海、纽约显示，不修改后台的时间窗口。

## 取舍与后续

保留本地 SQL/全文检索，避免为三份 PDF 引入向量服务；保留联合版本、SkillRegistry 和 Model 接口供未来扩展。首版只有一套规则函数，不做微服务或多模型路由。生产身份核验/真实支付/GDS、生产多实例、完整历史执行器迁移、实时航班事件、真正人工审批和额度兑换都在本期之外。

投入以实际开发和验收记录为准；没有按任务书六小时上限倒填完成，也不把自动化等待算作人工工时。最新验证和时间记录见 [VALIDATION](VALIDATION.md)。
