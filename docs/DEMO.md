# 演示与复现

默认启动页面：`http://127.0.0.1:3000`；当前复核实例：`http://127.0.0.1:3001`。三份政策、全部姓名/订单/航班/资金均为作业虚构资料。想验证边界用冻结时钟的独立库；日常交互使用实时时钟。不要在同一份已办理库上重复假定原票还未使用。

## 准备独立基线

先停止服务，再运行：

```sh
AIRLINE_DB=var/demo.sqlite AIRLINE_FIXED_TIME=2026-09-18T00:00:00Z npm run seed -- --reset
AIRLINE_DB=var/demo.sqlite AIRLINE_FIXED_TIME=2026-09-18T00:00:00Z npm start
```

页面显示冻结时钟，提醒这不是当前真实航班日期。以下是给用户的自然语言输入；后台已有的出票时间、票价、税额、旅客归属无需用户手工填写。手动体验金额以报价卡和当前数据为准。

执行下列客票样例前，点右上角“体验示例”（也可从登录框的同名页签进入），选择表中虚构身份。本地注册账号默认没有样票，不会自动取得林怡/陈平/代理权限。

## 十个场景

| ID | 身份与操作 | 预期及核对重点 |
|---|---|---|
| A01 | 游客：“行李能带多少？”；补充“Bluehaven BHA，Basic 票价。” | 先澄清航司；个人物品 1 件 3kg、40×30×15cm；无免费登机/托运行李；可另购登机箱 7kg/25 美元、托运行李 20kg/40 美元，每人每段；可点 PDF |
| A02 | 林怡：“显示我本人有权查看的客票”；随后声称付款人要求取消 `NSA-B` | 本人票可见，同行陈平的 `NSA-B` 不可见/不可办理；姓名或付款人声明不赋权；订单和资金不变 |
| A03 | 许悦代理，明确选 `NSA-A`、`NSA-B` 的两段，选择同档次、各涨价 30 的次日候选；先报价再点确认 | 四段手续费 100、正差价 120，共收 220；确认前不变，确认后四段同事务更新 |
| A04 | 林怡，分别为 `BHA-OLD-A`、`BHA-NEW-A` 提前改签报价 | 原出票在 7 月 1 日分界前为 85、等于分界为 55；自动化把请求精确放到 24h+1ms 报价、2ms 后确认，均拒绝旧资格且不收费；手动聊天不能修改服务器时间 |
| A05 | 林怡，为 `STA-MIX-A` 的国内和国际两段选择同价 Standard 候选 | 国内 20 + 国际 65 = 85；样例两段分别提前 30h、36h，均属 early，保留可行的顺序行程 |
| A06 | 林怡：“请给 `CANCEL-NSA-A` 整张票取消的方案，分别说明旅行额度、原路退款和不退的费用，暂不执行。”；检查后确认 | 票价 100 减取消费 40，发本人额度 60；税费原路退 20，座位 10 不退；不称现金退 80；额度 365 天，同行票不变 |
| A07 | 林怡：“请为 `BHA-DISRUPT-A` 申请航变整票退款，先给我确认前的明细。”；确认 | 航变恰好 180 分钟、Basic 全未用；票价 200 + 税 30 + 行李 40 + 座位 10，共原路模拟退 280；同一权益不能重复退或免费改 |
| A08 | 林怡：“请为 `NSA-PARTIAL-A` 已使用一段的客票，申请航变后未使用受影响部分退款，需要人工核定就请记录审核申请。” | 保留未用受影响部分退款权；金额待核定；本地记录待人工接入，订单和资金不变，不退款已飞部分 |
| A09 | 多个浏览器上下文各自咨询；林怡与代理分别给同一票报价后同时确认 | 十个会话不串历史；同票旧版本最多一笔成功，另一笔明确冲突；不同票合法操作可分别成功。自动化另行核对实际延迟，不承诺生产容量 |
| A10 | 独立基线取消 `CANCEL-NSA-A`，测试在提交完成后丢掉响应；原请求查询，再刷新 | 不以网络异常判断未执行；恢复同一操作编号，至多一次取消/退款/额度。故障只能由本地测试构造注入，聊天和网页不能设置 |

A03 可登录代理后输入“给 NSA-A 和 NSA-B 两位旅客的全部两段改签，保持 Standard，请提供选项让我选”，在同一候选卡为两人各选两段 Standard-1，再统一报价；U01 用真实模型完整复现此路径。自动化直接发送已选定的公开候选标识，仍经过真实模型选择工具、后端重新查事实和网页确认；没有将报价金额写进用户输入。

## 明确的新航班选择示例

候选卡的标识是选择项，不是授权凭据，也不是可自行编造的报价。A03 的冻结基线选项为：

```text
请为 NSA-A、NSA-B 两张票的全部两段改签到以下已选择的新航班，先报价，不要执行：
NSA-A-S1 → NSA-A-S1-Standard-1
NSA-A-S2 → NSA-A-S2-Standard-1
NSA-B-S1 → NSA-B-S1-Standard-1
NSA-B-S2 → NSA-B-S2-Standard-1
```

如果日期或目标不明确，助手可以要求补充或显示候选，不能任意挑第一班。示例仅对应该初始基线，办理后必须重新查当前事实。

## 其他入口与反例

- 登录后可点“处理记录”，不需要再次问模型，就能查当前权限下已完成的操作和本地审核单。
- 聊天输入“确认”只会展示当前可确认方案；只有卡片上的具体按钮能提交。
- 报价超过 5 分钟、客票版本变化、授权变化、当前政策条件变化或座位不足，都不能继续原方案。
- 询问宠物、贵宾室、真实航空公司政策等资料未覆盖主题，应说明无法确认，而非推定允许或禁止。
- `AGENT-NSA-A` 的退款需原出票代理；`STA-MISSED-A` 展示误机边界；三家 `*-BASIC-A`、`*-STANDARD-A`、`*-FLEX-A` 可比较不同票价。
- 已取消票的未用税如果已经随取消退款，另起退税报价仍不得重复领取。

## 实际报告

运行 `npm run acceptance` 会新建十个独立基线，从浏览器自然语言输入开始，保留页面文本/截图、真实模型工具调用、联合版本与最终数据库结果。浏览器故障/交互测试单独使用模型替身，报告清楚区分。实际通过状态以 [VALIDATION](VALIDATION.md) 和对应 JSON 为准，不以本页预期表替代。
