# 多实例会话冲突修复

日期：2026-09-20。用户报告页面只能问一次、点击后清空或无结果，并出现“会话已过期”。

## 根因与复现

用户浏览器同时打开 `127.0.0.1:3000` 和 `127.0.0.1:3001`。旧版与复核版连接不同数据库，但都写入同名 `airline_session` Cookie。Cookie 不按端口隔离；两页15秒检查和聚焦检查交替覆盖 Cookie，各服务读到不属于自己的会话，创建新游客会话。前端发现身份变化后重新初始化，导致原有对话看似刷新、正在完成的答复不可见。

两个实际数据库中均观察到约15秒间隔新建会话；共享HTTP Cookie容器按3001→3000→3001访问，[修复前返回的会话发生变化](../evals/session-fix/before.json)。新增真实浏览器双实例测试也在修复前失败：第二轮后只剩一条消息，[原始失败记录](../evals/session-fix/browser-before.log)。因此不是聊天次数限制，也不是截图显示的真实30分钟到期。

## 修复

- 每个数据库保存独立、稳定的随机Cookie命名空间，重启不改变。登录、退出、读取和CSRF校验都使用该命名空间。
- 只有本数据库仍有效的旧Cookie可在初始化时迁移；不续延后台闲置期限，不接受别的实例身份。新Cookie存在但无效时，不退回旧身份。
- 保留30分钟闲置、8小时绝对时限、身份切换隔离及显式确认规则。没有通过关闭后台检查、延长到期时间或清空业务库规避问题。
- 更新验收脚本，按实际实例的Cookie名称查找会话。
